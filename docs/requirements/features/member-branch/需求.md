# 成员分支：新建、切换、提交

> **状态**：实现中（2026-11-07）  
> **最后更新**：2026-11-07  
> **Feature ID**：`member-branch`

## 1. 背景与目标

- **问题**：工作区能把所有成员切到同名分支（`ws branch-switch`），界面也能做这件事。不能对**一个成员**新建分支、切到该分支，再只提交这个成员。
- **目标用户 / 场景**：在规范库或工具库成员上开一条自己的分支，改完后提交该成员，不带动其他成员。

## 2. 范围

### IN SCOPE

- 选定一个成员后：列出它的本地分支、新建分支、切换到已有分支。
- 在该成员当前分支上提交，只产生这个成员的 commit。
- 成员工作树脏时拒绝切换，并列出脏路径。
- 切换和提交的结果回到成员行：当前分支名、HEAD。

### OUT OF SCOPE

- 改 ADR-0012 的工作区分支映射（同名分支同时切所有成员）——保留，不删。
- 自动合并、自动解决冲突。
- 单成员提交写入 Revision（开放问题 1，仍未做）。

### 依赖 / 阻塞

- 核心已有 `ws branch-list` / `branch-create` / `branch-switch`，切换作用于**每个**成员。
- 界面协议只有 `ws.switch`，没有按成员创建、按成员切换、按成员提交。

## 3. 用户故事与主流程

### 故事 1

- **Given** 工作区有成员 `spec`，当前在 `main`，工作树干净
- **When** 用户在 `spec` 上新建 `feature/ui` 并切换过去
- **Then** 只有 `spec` 变为 `feature/ui`，其他成员分支不变

### 故事 2

- **Given** `spec` 在 `feature/ui` 上有未提交改动
- **When** 用户填写说明并提交该成员
- **Then** 只在 `spec` 产生 commit，主仓和其他成员没有新 commit

### 主流程

1. 在成员行打开分支。
2. 新建或选用一个分支，只检出这个成员。
3. 提交这个成员。
4. 成员行显示新的分支名和 HEAD。

## 4. 验收标准

- [ ] 两个成员处于不同分支时，对其中一个新建并切换，另一个的分支名不变。
- [ ] 成员脏时切换被拒绝，分支不改变。
- [ ] 成员提交后，`git -C <成员路径> log -1` 有新 commit，主仓 `git log -1` 不变。
- [ ] 只读成员（`readonly`）不能新建分支，也不能提交。

## 5. 边界与异常

| 场景 | 期望行为 |
|------|----------|
| 分支名已存在 | 不覆盖，提示改用「切换」 |
| 成员缺失 | 按钮不可用 |
| 提交说明为空 | 不调用 git |
| 只读成员 | 拒绝新建、切换、提交 |

## 6. API / 数据契约（草案）

沿用 JSON 操作，不新开 HTTP。

| 操作 | 说明 |
|------|------|
| `ws.branch.list` | 已有 `ws.branches`，按成员返回当前分支 |
| `ws.branch.create` | 增加 `member`；缺省时保持今天的「所有成员同名」 |
| `ws.branch.switch` | 增加 `member`；缺省时保持今天的全员切换 |
| `member.commit` | `member` + `message`，只提交该成员 |

## 7. 前端要点

- 落在工作区页的成员行，不把「全员同名切换」和「单成员分支」画成同一个按钮。
- 全员切换仍留在「主仓与分支」折叠区。
