## 1. 设计原则

| 原则 | 在本能力里意味着 | 明确不做什么 |
|------|------------------|--------------|
| 分支语义仍交给 git | 创建、切换、提交都调用 `git` | 不自研分支对象 |
| 工作区分支映射保留 | 不带 `member` 的切换仍是全员同名（ADR-0012） | 不删除现有 `ws branch-switch` |
| 一次只动一个成员 | 带 `member` 的操作只进入该成员的工作树 | 不在单成员提交时顺带提交主仓 |

## 2. 模型

一个成员有自己的 HEAD 分支。工作区分支是「每个成员的分支名」的映射，继续存现有 ref。两者并存：

- 全员切换：映射里每个成员都改成同一个名字。
- 单成员切换：只改这一个成员的检出，映射里只更新这一条。

只读成员没有写分支。`editable`、`local`、`main` 可以新建和提交。

## 3. 交互

成员行增加「分支」，展开后是：当前分支、已有分支列表、新建名称、提交说明。

1. 新建：`git switch -c <name>`，仅该成员。已存在则停。
2. 使用：`git switch <name>`，仅该成员。脏则停并列出路径。
3. 提交：在该成员 `git add` 已选路径（缺省为该成员全部改动）后 `git commit`。不调用主仓 commit。

成功后成员行的分支名和 HEAD 更新。失败文字留在这一行，不占用整页。

## 4. 模块

- 渲染层：工作区页成员行。不在页面里拼 git 命令。
- 主进程：转发新的 op。
- `crates/core`：在现有 `workspace::branch_*` 上增加成员过滤；提交复用成员仓的 git commit，不走主仓 Revision 流程，直到开放问题 1 关闭。

## 5. 施工

单成员入口在成员行「分支」。全员同名切换留在「主仓与分支」。实现见 `实现方案.md`。
