# 决策记忆

## 2026-11-07 · 桌面端以修订刻度为第一屏

- **决定**：总览和工作区的第一屏是当前工作区的修订读数。成员对齐是唯一主操作（先更新 pin，再按 lock 检出）。里程碑代号和渐变标志撤出界面。
- **为何**：七个导航和同权重按钮让「拉取规范库」没有一条路径。
- **不选**：不换色板、不换字族、不给每个页面单独做皮肤。

## 2026-11-07 · 成员分支单独记一笔，本轮不实现

- **决定**：单成员的新建分支、切换、提交记在 `docs/requirements/features/member-branch/`。现有「全员切到同名分支」保留。
- **为何**：用户要在一个成员上开分支并提交，今天的切换会带动每个成员。
- **不选**：不在这一轮改 Rust 核心或协议。

## 2026-11-07 · 操作反馈改成短时浮层，主色改成修订印

- **决定**：点按钮后的成功和失败不再占页面横幅，改成右下角可关掉的短时浮层。状态本身（没选项目、没声明工作区、缺核心）仍留在页面上。按钮间距从 8px 提到 16px。底色改成墨色，主按钮用实心琥珀色，字是深色。
- **为何**：横幅会一直留在页面上；青绿半透明主按钮和 8px 间距让「日志、钩子和运行时」挤成一团。
- **不选**：不加组件库，不换字体。概念未另派独立生成，只留这一个方向。

## 2026-11-07 · 1.0 门槛里先落下能核实的三块

- **决定**：发布只带一个 Rust 二进制 `gitmove-core.exe`（命令行和 `mcp` 子命令）。界面经 sidecar 调它，不再保留 Python 引擎字段。1.x 金样里和核心有关的三条（中文路径不被 quotePath 改写、无备份目标不崩溃、junction 指向外部目录）锁进 `crates/core/tests/golden_v1.rs`。命令行 `--json ws status` 与 MCP `gitmove_ws_status` 必须读到同一份成员数据，锁进 `crates/cli/tests/read_parity.rs`。
- **为何**：这三块是 M4/M5/M6 里现在就能对照代码核实的部分。Python 1.1 的测试多数是 Tk 界面，v2 已经换成 Electron，整包搬过来对不上。
- **不选**：不把 1.1 的 73 个测试文件改写成 Rust，也不把发行物再做成「一个文件里连 Electron 一起」。

## 2026-11-07 · 1.0.0 按三条里程碑发布

- **决定**：版本定为 1.0.0。金样补上密码文件不得入库、skip-worktree、超大暂存文件。命令行与 MCP 对工作区状态、提交后查看、脏工作区回滚、无目标备份、主仓回推这五次读到同一结果。安装包只带 `gitmove-core.exe`。
- **为何**：这是需求里 M4/M5/M6 现在能核实的退出条件。Tk 界面测试留在 Python 仓库。
- **不选**：不把仍未做的 2.1 远程备份算进这个版本号。
